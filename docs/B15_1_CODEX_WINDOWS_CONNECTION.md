# B-15.1 — Local Codex connection (opt-in)

Baseline: approved `main` merge `c3b060a` (Aquila B canonical and native title-strip repair). Do **not** replace approved sprite assets or rewrite the existing black square menu.

## What is and is not connected

The current Aquila executable receives local JSONL events and has three manual test buttons. B-15.1 adds a **user-level Codex lifecycle hook installer**, so `UserPromptSubmit` events from **trusted local Codex sessions across projects** can append `jobStart` to the event file. <https://developers.openai.com/docs/hooks> documents the supported lifecycle hooks and approval.

Local app behavior: on receiving `jobStart`, Aquila plays the approved Working event sequence. It does not identify the source of every local JSONL row as Codex; external event rows can also come from verification scripts.

It **does not** read prompts, transcripts, model tokens or credentials; it never invokes the Codex API or posts to a server. It cannot automatically monitor remote/cloud Codex sessions if their sandbox cannot reach the Windows user's app-data folder. Codex trust, runtime hook execution and desktop application event reception must be verified **on the user's real PC**.

`testPassed` and `deploymentComplete` are **not** automatically generated by a generic Codex Stop/success notification. Use known successful test results or verified deployment events only. A completed model turn is *not* a passed test or successful deployment.

## Install from the QA ZIP on Windows

1. Extract the *entire* B-15.1 Windows QA ZIP. Close old pet processes, then run `CastlePet.exe`.
2. Install a Node.js runtime if needed and open PowerShell in the extracted QA folder.
3. Inspect the included scripts `scripts/setup-codex-integration.mjs` and `scripts/codex-hook.mjs`.
4. Run **explicitly**:
   ```powershell
   node .\scripts\setup-codex-integration.mjs install
   node .\scripts\setup-codex-integration.mjs status
   ```
5. In a **local** Codex client, open `/hooks` and review/approve the `Castle Desktop Pet — local job-start event` user hook. Restart/reload Codex if needed.
6. Submit one simple prompt. Open Aquila's **더보기 → 현재 상태** to inspect the configured hook and the received external event. If the pet had an active manual pose, the event may be blocked according to existing action priorities.

Settings are stored in `%USERPROFILE%\.codex\hooks.json` (or `%CODEX_HOME%\hooks.json`). The hook script is copied into the stable `%APPDATA%\castle-desktop-pet\integration\codex-hook.mjs`, **not** referenced from the temporary ZIP extraction folder. The default Windows event file is `%APPDATA%\castle-desktop-pet\codex-events.jsonl`. For a custom `CODEX_HOME` or custom app-data location, confirm the app's status-panel path. The installer preserves unrelated hooks and backs up an existing config once with `.castle-pet-backup`.

## Uninstall or debug

```powershell
node .\scripts\setup-codex-integration.mjs uninstall
```
This removes only the Castle Desktop Pet `UserPromptSubmit` hook group, leaving other Codex hooks intact. The standalone hook script stays in app data and cannot trigger itself once removed.

- The source repository also has a project-local `.codex/hooks.json`. Running **both** that hook and the global hook while working in this exact repository may send duplicate `jobStart` events. Use only one hook for local work in this repository.
- Without trusting/approving hooks, Codex may skip execution. Installed is **not** connected.
- If Codex runs in a remote sandbox, WSL environment or browser cloud, the default Windows path may be inaccessible.
- Use the old B-15 manual test buttons to verify app behavior independently of the Codex hook.
- For a known successful local project test:
  ```powershell
  npm test
  if ($LASTEXITCODE -eq 0) { node scripts/emit-codex-event.mjs testPassed }
  ```
  Execute this last command from the source checkout, **not** from the portable QA folder.
- Emit `deploymentComplete` only after independently verifying success.

## Release policy

This feature remains on `feat/b15-1-codex-local-connection` until the user reviews the Windows result. Do not merge or deploy new functionality without separate approval. The current merged `main` is the baseline, not B-15.1.

## B-15.3 Settings & integration UI (2026-11-10)
- **빈도** has three independent **1–15 minute** sliders for autonomous
  movement, autonomous dialogue and automatic firing cooldown. Existing
  saved quiet/default/active presets remain valid until replaced; after
  slider adjustment the selected minutes are fixed, rather than random.
- Original per-action relative weights (0–40) remain independent, and
  manually triggered firing bypasses the auto cooldown.
- Changing the selected minute values does not interrupt a current
  manually held action or a Codex event; affected schedules are rearmed.
- The black square settings window remains rectangular, but its
  background is now a brighter charcoal with clearer borders and
  highlighted selected controls.
- **더보기 → 현재 상태** provides a sliding Codex hook ON/OFF switch.
  Switching ON explicitly installs only the trusted local hook in the
  user's Codex config; OFF removes only the hook group owned by the pet.
  The switch reflects the saved hook setting, not an unverified cloud
  connection. A status message reports installation errors.
- This build needs user-side testing of real Windows Codex hook
  approval/reception; no main merge or Release without the user's review.
