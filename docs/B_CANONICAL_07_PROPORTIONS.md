# B-CANONICAL-07 — 비례 편집 후보 (미승인)

기준 커밋: 최신 main `42d9c83e732004b00b97b3776cd45923f6f8153d`.
공식 B형 원본 9종, 해시 목록, 기본 `action-pack-v04`, 의상 등록 및 Electron 코드는 변경하지 않았다. 이번 대상은 Idle / Smoking / Sitting 세 포즈뿐이다.

## 결과와 한계

`src/characters/candidates/b-mustang-20261107/proportions-v07/`에 실제 투명 PNG 편집 후보 3종과 해시·원본 좌표 기준점 manifest를 별도로 보관한다. 캔버스 정렬이나 전체 확대·축소로 비례를 보정했다고 주장하지 않는다. 이미지 편집 모델에 각 공식 원본과 Drawing/Firing/Working 원본을 함께 입력하여 머리 대 몸통·팔다리 비율을 바꾸었다. 기본 펫에는 등록하지 않았다.

- Idle: 머리를 상대적으로 줄이고 몸통·다리를 길게 만든 후보. 첫 시안의 머리가 너무 작아 재편집했다. 포켓 손, 내려간 손, 부츠와 기울어진 자세는 유지했으나 얼굴 인상·소매·봉제선·옷 주름이 재묘사되었다.
- Smoking: 같은 방향의 비례 편집. 첫 시안의 과도한 머리 축소를 재조정했다. 담배·연기와 손을 입으로 가져간 자세는 유지했다. 손가락/입술/담배 접점과 담배 길이, 연기 모양, 소매 세부는 원본과 완전히 같지 않다.
- Sitting: 머리 대 어깨 비율을 줄이고 상체를 길게 재편집했다. 상자 위에 앉아 무릎을 벌리고 아래로 총을 든 자세는 유지했다. 서 있는 전체 키를 맞추지 않았다. 노출된 목 길이 증가와 어깨 연결, 손·리볼버·상자 세부 변경 때문에 체형 일치와 자세 보존이 완성되었다고 판정하지 않는다.

전체적으로 머리·몸의 상대 비율 변화는 눈으로 확인되지만, 포즈 전체를 재편집한 결과 세부 픽셀 보존은 보장할 수 없다. 흉터를 추가하지 않도록 지시했으며 새 흉터는 관찰하지 못했다. 이마 주름과 표정 동일성은 사용자가 원본과 비교해야 한다. 원본의 일부 붉은 경계도 남아 있다. **세 이미지 모두 검수용 후보이며 최종 완성·시각 승인·실행 적용 상태가 아니다.** 정확한 손·소품·선화 동일성을 확보하려면 작가의 국소 재작화가 필요하다. 모델 출력을 다시 생성해 같은 PNG가 나오는 것은 보장되지 않으므로 현재 후보 자체와 SHA-256을 버전 관리한다.

## 비교 방법

`npm run preview:package` 후 `preview.html`의 **B-CANONICAL-07** 구역에서 대상, 180/240/360px, 배경 및 가이드를 선택한다. 원본·후보·Drawing/Firing/Working 5개를 동일 너비/높이의 표시 영역에 보여 준다. 좁은 화면에서는 줄을 바꾸며, 종횡비는 유지한다. 투명 여백을 포함한 파일 크기 기준이며 실제 인체 높이를 자동 일치시키는 기능은 없다.

머리 상자, 눈높이, 어깨선, 발선은 각 이미지에서 수동으로 추정한 좌표를 따로 표시한다. 고정 캔버스 선을 인체 계측으로 제시하지 않는다. 머리폭/어깨폭 수치는 같은 포즈의 변화 방향을 살펴보는 보조치일 뿐이며, 어깨 회전과 원근이 다른 Sitting을 서 있는 포즈의 수치로 합격 처리하지 않는다. 머리 모양·눈높이·어깨 연결·상하체·발 위치를 함께 검수한다.

검수 의견은 기존 기록 화면의 `07 후보 idle/smoking/sitting`을 선택한다. JSON 키 `b07/idle`, `b07/smoking`, `b07/sitting`을 사용하여 기존 원본 의견과 섞이지 않는다. 기존 로컬 저장/수동 JSON 내보내기 흐름을 유지하며 자동 시각 승인을 기록하지 않는다.

동일 크기 비교 자료: [Idle](b07-review/idle.png), [Smoking](b07-review/smoking.png), [Sitting](b07-review/sitting.png). Dual Firing / Firing Dynamic / Speaking의 기존 이미지 진단과 의견 내보내기도 유지한다.

## 위험·검증

검수 모듈을 `preview.ts`에만 연결하여 실행 에셋 혼입을 방지한다. 원본/후보 해시·PNG 크기 및 실행 진입점 격리 테스트를 추가했다. 기존 의견 키와 후보 의견 키를 분리하고 실제 브라우저에서 원본 기록 오염과 내보내기를 확인한다. 이번 변경에는 런타임 리팩터링이 불필요하다. 검수 경계만 별도 모듈로 두었고 기존 애니메이션·저장·창 로직을 수정하지 않았다. 재검토 계기는 후보가 실제 의상 등록 대상으로 승인되는 시점이다.

브라우저 QA 테스트 서버의 `/favicon.ico` 요청에 204를 반환하도록 수정했다. 기존 콘솔 오류 assertion은 유지하며, 앱 기능과 무관한 404 때문에 전체 QA가 실패하던 원인을 제거했다.

검증 결과: 빌드·Node 테스트 45개·원본 SHA-256 9종·미리보기 ZIP 생성 통과. 새 브라우저 QA는 3포즈 × 3크기 로딩/같은 표시 너비, 가이드/배경 조작, 기존 제외 포즈 진단 접근, 후보 의견과 원본 의견 분리/JSON 내보내기 통과([보고서](b07-review/report.json)). 기존 전체 브라우저 QA 72항목, 동작 재생/완료/취소/일시정지/반복/Reduced Motion QA, 기존 검수 JSON/이미지 요청 취소 QA 통과. 최종 편집 이후 빌드·45개 테스트·새 비교 QA·기존 검수 JSON QA를 다시 실행했다.

Windows 실제 입력·투명 창과 최종 이미지 시각 승인은 이 Linux 환경에서 통과했다고 주장하지 않는다. 기존 Windows smoke 워크플로는 유지하며 원격 CI 완료는 별도 확인이 필요하다. 파일 오프라인 검사는 관리형 Chromium의 `file://` 정책 때문에 실행 차단된다(`ERR_BLOCKED_BY_ADMINISTRATOR`); HTTP에서의 이미지 로딩 검증과 ZIP 생성 성공은 이 제한을 대신하는 오프라인 성공 판정이 아니다.
