# B-13.3 안정화·메뉴 UX 검수

기준 `01eadb3`, 작업 브랜치 `feat/b-canonical-07-proportions`, Draft PR #11. 승인 B형 PNG·원본/파생 SHA·런타임 매핑과 사격/대사/독립 스케줄러를 유지한다. 이미지 재생성, npm 의존성 추가, main 병합·Release·배포는 없다.

## 제목 표시줄/불투명 영역: 확인한 사실과 한계

사용자는 ZIP 폴더에서 electron을 실행했다고 설명했고, 캐릭터 뒤에 `Castle Desktop Pet` 제목 띠가 겹친 캡처를 제공했다. **캡처만으로 그 HWND의 프로세스·실행 파일 버전을 확정할 수는 없다.** ZIP 직접 실행이나 이전 프로세스가 원인이라고 단정하지 않는다.

기존 코드에 이미 투명·frameless 설정이 있었다. B-13.2 그대로에 읽기 전용 Win32 검사를 추가한 [기준 Windows 실행](https://github.com/pchjesus/castle-desktop-pet/actions/runs/42550829333)의 결과:

| 창 | 실제 WS_CAPTION | WS_EX_LAYERED | 역할 |
| --- | --- | --- | --- |
| 펫 본창 | false | true | dist/index.html |
| 대사창 | false | true | pet-speech.html |
| 진단창 | true | false | 별도 preview.html 도구 |

따라서 같은 옵션을 반복 추가하거나 GPU/Windows 설정을 추측으로 변경하지 않았다. 다음 실행 경계와 검사를 보강했다.

- 최상위 **CastlePet.exe**만 사용자 실행 진입점으로 제공한다. 원래 Electron 및 앱 리소스는 `runtime/` 내부로 분리했다. 실행기는 Windows 기본 .NET Framework로 빌드되며 셸·네트워크·관리자 권한을 사용하지 않는다.
- 실행 전 전체 폴더와 main/HTML 해시를 검사한다. ZIP에서 실행기만 임시 추출되거나 파일이 섞인 경우 Electron을 시작하지 않고 **전체 압축 풀기**를 안내한다. vendor default_app.asar fallback은 제거했다.
- 실행기는 정확한 앱 폴더를 명시해 내부 Electron을 시작한다. 내부 electron.exe 직접 실행은 안내 후 종료한다. 개발용 npm start는 유지한다. 중복 실행 잠금과 안내를 추가했으며, 이전 다른 Electron 프로세스를 임의 종료하지 않는다.
- 펫·진단창의 운영체제 제목을 역할별로 구분했다. 진단 도구는 메뉴 ‘더보기’에서만 여는 별도 불투명 창이다. 기본 펫 실행은 진단창을 열지 않는다. 실제 실행 파일/entry/resources 경로는 로컬 qa.log에 기록한다.
- 기존 네 모서리 검사로 놓칠 수 있던 **중간 제목 띠**를 검출하도록 투명 영역 전체의 안정적인 표본을 검사한다. Node 회귀 테스트는 모서리는 투명하지만 중간에 불투명 띠가 있는 경우를 실제 실패로 판정한다.
- 정상 실행 경로도 별도 검사한다: CastlePet.exe → 리소스 검증 → 일반 펫 시작(진단창 없음). Windows 데스크톱을 실행 전후 비교하고 실제 창 스타일·이미지 로딩을 기록한다. 테스트 전용 smoke 경로의 결과만으로 정상 실행을 대체하지 않는다.

**남은 구분:** 사용자 실기기의 원래 캡처를 동일 프로세스로 재현한 것은 아니다. Windows 자동 검수의 정상 경로 결과와 원래 사용자 프로세스의 원인 확정은 서로 다르다. 새 패키지는 기존 펫 종료 → ZIP 전체를 새 폴더에 압축 풀기 → `검수 QA/CastlePet.exe` 순서로 실기기 시각 확인이 필요하다.

## 연기

이전 보조 연기는 표시 크기에 따라 1px 미만의 선·낮은 불투명도로 그려졌고, Reduced Motion에서 레이어를 아예 제거했다. 기존 Windows 러너의 실제 설정도 Reduced Motion이었다. 사용자 PC의 해당 설정은 확인하지 않았다.

새 연기는 담배 끝 원본 좌표 `(597,282)`, 캔버스 `1003×1568`을 유지하며 최소 **2px** 선과 명암 경계를 사용한다. 일반 모션은 두 줄이 2초마다 상승·휘어짐·소멸한다. Reduced Motion은 **이동·확대 없이** 불투명도만 `.25↔.65`로 완만하게 반복한다. 따라서 해당 설정에서도 연기 표시가 완전히 사라지지 않는다. 숨김·포즈 이탈·종료 시 레이어와 관찰자를 정리한다.

승인 PNG 안의 고정된 연기는 그대로다. 연기 자체가 바뀌는 픽셀 비교를 위해 Windows QA에서는 캐릭터 호흡만 일시 고정하고 보조 연기 ON/OFF와 500ms 간격 프레임을 비교한 뒤 원래 연출을 복구한다. 이는 ‘CSS 노드가 있음’ 검사를 실제 보이는 효과 검증으로 보완한다.

## Sitting/Working 클릭

이전 일반 클릭은 무조건 기본 자세를 그리고, 반응 완료 시 다시 기본 자세로 복귀했다. Sitting/Working 및 수동 유지한 휴식 자세는 이제 **같은 자세에서** 짧은 대사/무언 반응을 한다. 자동 Sitting에 클릭하면 사용자 유지 상태로 전환해 이전 자동 종료 타이머도 취소한다. 드래그도 자세를 유지하며, 오래된 드래그 종료가 더 새 수동 명령을 덮어쓰지 못하게 했다.

5번째 클릭은 기존처럼 Drawing 경고로 전환하고, 6번째는 확정 블랙맘바 대사를 출력한다. 그 이후 연타 무시·기본 자세 복귀 규칙은 그대로다. 이 경고 전환은 일반 클릭의 자세 유지와 구분한다.

## 말풍선

승인 포즈별 머리 영역과 원본 contain/letterbox 비율을 기준으로 **머리 가까운 좌상단**을 우선한다. 짧은 대사는 실제 보이는 폭으로 줄이고, 긴 대사는 최대 228px에서 줄바꿈한다. 먼저 크기를 측정하고 위치 확정 신호를 받은 뒤 표시해 빈 여백과 최초 위치 튐을 줄였다.

따뜻한 흰색 바탕·짙은 글자·꼬리를 사용한다. 위/왼쪽 공간이 부족하면 반대쪽/측면으로 옮기며 얼굴과 화면 경계를 피한다. 독립 투명·클릭 통과 창을 유지하므로 펫의 크기·발 위치·저장 좌표는 바뀌지 않는다. 대사 표시/페이드 및 Dynamic의 1초 준비·1.5초 사격·.85초 여운은 유지한다.

## 메뉴

기존 270×486px에서 **316×316px**로 높이를 약 **35%** 줄였다. ‘기본·빈도·동작·더보기’ 네 탭이 각각 스크롤 없이 들어간다.

- 기본: 평소 자세, 자동 움직임/대사/사격, 전체 9개 크기 및 ±.
- 빈도: 움직임·대사를 각각 ‘조용히/보통/활발히’와 실제 분 단위로 표시.
- 동작: 9포즈를 한글로 표시. ‘허리 사격’은 기존 Firing Dynamic이다.
- 더보기: 기존 전체 검수 및 세 종류 원본/후보/표정 비교. 펫 종료·Esc 닫기·키보드 탭 이동·자동 저장도 유지.

## 검증 및 사용자 패키지

기존 자산 SHA, 9포즈·Speaking 7컷·사격/쿨다운·독립 타이머·5/6회 클릭·투명 입력·드래그/크기/저장을 유지한다. 새 테스트는 유지 자세 클릭/드래그, 전체 투명 영역의 불투명 띠 검출, 머리 보호 배치, 짧은/긴 말풍선 크기, 316px 메뉴 전체 탭·키보드·크기 변경, Reduced Motion의 정지 연기를 검사한다.

Windows 워크플로는 실제 메뉴 입력/18개 포즈 명령, Sitting/Working 클릭 후 대사 종료까지 자세 유지, 연기 픽셀 변화, 모든 메뉴 탭 캡처, 일반 실행 경로, 불완전 압축 해제 거부를 추가 검증한다. 정상 경로 결과는 `windows-plain-launch.json`, smoke 결과는 `windows-qa-report.json`, 새 GUI 캡처는 `windows-b13-3-captures/`에 있다.

최종 통과 여부는 [PR #11](https://github.com/pchjesus/castle-desktop-pet/pull/11)의 해당 커밋 CI 및 [Windows 워크플로](https://github.com/pchjesus/castle-desktop-pet/actions/workflows/windows-smoke.yml)를 확인한다. **castle-pet-windows-b13-3-qa-unapproved** 아티팩트 전체를 압축 풀기 하고 `검수 QA/CastlePet.exe`를 실행한다. 실패한 실행의 아티팩트는 진단 자료이며 검수 완료본으로 안내하지 않는다.

실제 사용자 Windows 10/11의 수동 시각 승인·혼합 DPI/멀티 모니터 환경은 자동 Windows GUI 검사와 별도다. 전체 앱 리팩터링 대신 실행 경계, 클릭 복귀, 말풍선 레이아웃, 메뉴와 효과만 국소 변경했다. 원래 사용자 HWND의 제목 띠 원인은 단정하지 않았으며, 재현되지 않은 환경을 해결됐다고 기록하지 않는다.
